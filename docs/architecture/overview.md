# Архитектура: обзор

DeepSeek Automation API — это локальный прокси-сервер, эмулирующий
OpenAI API поверх веб-интерфейса DeepSeek. Сервер автоматизирует
браузер через Playwright и транслирует HTTP-запросы в UI-операции.

## Карта системы

```
┌─────────────────────────────────────────────────────────────┐
│  OpenAI-совместимый клиент (curl, SDK, чат-бот)             │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP
┌──────────────────────────▼──────────────────────────────────┐
│  server.js (Express)                                        │
│  ├── middleware.js     — rate limit, auth                   │
│  ├── routes/register   — создание сессии                    │
│  ├── routes/chat       — основной эндпоинт                  │
│  ├── routes/files      — загрузка (OpenAI file API)         │
│  ├── routes/single     — временный чат                      │
│  └── selector-validator — проверка селекторов при старте    │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│  DeepSeekClient (src/)                                      │
│  ├── BrowserManager      — Playwright, clipboard, webdriver │
│  ├── AuthManager         — логин (авто / ручной)            │
│  ├── ChatController      — отправка, ожидание, переходы     │
│  ├── ResponseExtractor   — Copy, fallback, баннеры          │
│  ├── FeatureToggles      — DeepThink, Web Search            │
│  ├── FileUploader        — загрузка, оценка размера         │
│  ├── ContextManager      — счётчики, снапшоты, язык         │
│  ├── TaskQueue           — сериализация UI-задач            │
│  └── RAG (опционально)                                      │
│      ├── HistoryStore    — индекс, поиск                    │
│      ├── LinearIndex     — векторы, cosine similarity       │
│      ├── RealEmbedding   — Xenova/all-MiniLM-L6-v2          │
│      └── IndexingQueue   — фоновая индексация               │
└──────────────────────────┬──────────────────────────────────┘
                           │ Playwright
┌──────────────────────────▼──────────────────────────────────┐
│  chat.deepseek.com (веб-интерфейс)                          │
└─────────────────────────────────────────────────────────────┘
```

## Три уровня состояния

| Уровень | Файл | Владелец | Содержимое |
|---|---|---|---|
| Браузер | `state.json` | `BrowserManager` | Cookies, origins |
| Чат | `chat_state.json` | `DeepSeekClient` | `lastChatId`, `totalChars`, флаги снапшота |
| RAG | `rag_data/<key>.linear.json` | `HistoryStore` | Векторы и метаданные |

Разделение критично: `server.js` при старте перезаписывает `state.json`
(после валидации селекторов). Если бы `chat_state` жил там же, он бы
стирался при каждом запуске.

## Ключевые решения

**Playwright, а не requests.** DeepSeek Web защищён от простого
HTTP-скрейпинга (Cloudflare, JS-челленджи). Playwright проходит
проверки и эмулирует реальный браузер.

**Одна страница, одна очередь задач.** Все UI-операции сериализуются
через `TaskQueue`. Параллельный доступ к DOM привёл бы к гонкам.

**Изолированный clipboard.** DeepSeek пишет в `navigator.clipboard`,
а не в DOM. В общем профиле Chromium один запрос мог бы прочитать то,
что скопировал другой. Clipboard подменяется на in-page буфер.

**Три независимых recovery-флага.** `ENABLE_RESTORE`, `ENABLE_SNAPSHOT`,
`ENABLE_RAG` комбинируются. Пользователь выбирает сценарий:
восстановить сессию, сжимать контекст, помнить всё.

## Что не входит в архитектуру

- Парсинг PDF/DOCX (используется то, что DeepSeek принял через UI).
- Внешние vector DB (FAISS, Qdrant) — индекс линейный, в JSON.
- Стриминг ответов — ответ возвращается целиком.
- Мульти-тенантность — одна сессия на процесс.
