# Обработка файлов

Алгоритмы F1–F4 описывают классификацию, оценку размера, загрузку
в UI и обработку ошибок при загрузке файлов.

---

## F1. Классификация по расширению {#f1}
**Статус:** active
**Дата фиксации:** 2026-09-18
**Версия:** 1

### Назначение

Определить, как обрабатывать файл: как текст (индексировать),
как изображение (оценивать по токенам), как документ (не индексировать),
или отклонить.

### Входные данные

- `filePath: string` — путь к файлу (или `ext: string`).

### Выходные данные

- Одна из категорий: `'text' | 'image' | 'office' | 'binary' | 'unknown'`.
- Для upload-валидации: `boolean` — поддерживает ли DeepSeek.

### Псевдокод

```
getFileCategory(filePath):
  ext := path.extname(filePath).toLowerCase()
  Если ext в UTF8_TEXT_EXTENSIONS:  вернуть 'text'
  Если ext в PARSABLE_EXTENSIONS:   вернуть 'office'
  Если ext в BINARY_EXTENSIONS:     вернуть 'binary'
  Если isImageFile(filePath):       вернуть 'image'
  Вернуть 'unknown'

isSupportedByDeepSeek(ext):
  Вернуть ext в DEEPSEEK_SUPPORTED_EXTENSIONS

isIndexableFile(filePath):
  Если ext не в UTF8_TEXT_EXTENSIONS: вернуть false
  content := readFileSync (первая проверка)
  Если content содержит '\0': вернуть false
  Вернуть true
```

### Граничные случаи

- **Файл с расширением `.txt`, но с null-байтом внутри.** Не индексируется —
  это бинарь, названный как текст.
- **Файл без расширения.** `'unknown'`, не индексируется, может быть
  загружен, если DeepSeek примет (маловероятно).
- **`.svg` — он и в TEXT, и в IMAGE.** Классифицируется как `'text'`
  (приоритет первого набора).

### Почему именно так

**Почему три набора, а не один.** Разные наборы нужны для разных решений:
- UTF8 — можно читать как текст и индексировать.
- PARSABLE (PDF, DOCX) — DeepSeek примет, но мы не парсим.
- BINARY — DeepSeek не примет (кроме изображений).

**Почему `isIndexableFile` проверяет null-байт.** Расширение — догадка.
Null-байт — почти достоверный признак бинарного содержимого. Двойная
проверка отсеивает файлы `.txt` с бинарным содержимым.

**Почему DEEPSEEK_SUPPORTED_EXTENSIONS отдельно.** Это копия accept-атрибута
файлового input на chat.deepseek.com. Если DeepSeek изменит список,
достаточно поправить здесь — валидация на сервере не пропустит
неподдерживаемый файл.

### Реализация

- `src/utils/fileUtils.ts`

## F2. Оценка размера (текст / изображение) {#f2}
**Статус:** active
**Дата фиксации:** 2026-09-18
**Версия:** 1

### Назначение

Оценить вклад файла в контекст в символах, чтобы обновить `totalChars`.

### Входные данные

- `filePath: string`.
- Языковой коэффициент из C1 (для изображений).

### Выходные данные

Число — оценка в символах.

### Псевдокод

```
getFileSizeInChars(filePath):
  Если isImageFile(filePath):
     Вернуть IMAGE_TOKENS (384) * languageCoefficient
  Попробовать: content := readFileSync(filePath, 'utf-8')
     Вернуть content.length
  Fallback (ошибка чтения):
     Вернуть размер файла в байтах
```

### Граничные случаи

- **Изображение.** Всегда 384 * коэффициент, независимо от разрешения.
- **Текстовый файл.** Длина в символах.
- **Нечитаемый файл.** Fallback на размер в байтах.

### Почему именно так

**Почему изображения оцениваются фиксированно.** DeepSeek Vision
даунсемплит изображение до 384 токенов независимо от исходного размера.
Оценка в байтах была бы неверной — картинка 10 МБ и 100 КБ дают
одинаковый контекст.

**Почему для текста длина в символах, а не в байтах.** `totalChars`
считает символы, а не байты. Для UTF-8 это разные числа (русская буква
= 2 байта, но 1 символ).

**Почему fallback на байты.** Если файл не читается как UTF-8,
это, скорее всего, бинарь. DeepSeek всё равно его не примет (кроме
изображений), но ошибка чтения не должна ломать подсчёт.

### Реализация

- `src/file/FileUploader.ts` → `getFileSizeInChars()`
- `src/utils/fileUtils.ts` → `IMAGE_TOKENS`

## F3. Загрузка файла в UI (attach) {#f3}
**Статус:** active
**Дата фиксации:** 2026-09-18
**Версия:** 2 (retry на Server Busy)

### Назначение

Прикрепить файл к полю ввода DeepSeek через UI-автоматизацию.

### Входные данные

- `files: string[]` — пути к файлам.

### Выходные данные

Файлы прикреплены, кнопка Send активна.

### Псевдокод

```
attachFile(files):
  // 1. Клик по скрепке через координаты (нативный диалог не открывается)
  textarea := page.$(mainTextarea)
  box := textarea.boundingBox()
  page.mouse.click(box.x + box.width + 40, box.y + box.height/2)
  page.keyboard.press('Escape')  // закрыть dropdown, если открылся

  // 2. Установить файлы напрямую через input
  inputs := page.$$(fileInput)
  inputs[last].setInputFiles(files)

  // 3. Ждать появления бейджа (SVG path)
  try:
     waitForSelector('svg path[d^="M10.6074 4.40278"]', 30000ms)
  catch:
     Если видно "format not supported": throw
     Иначе: throw "File badge did not appear"

  // 4. Retry loop на "Server busy"
  deadline := now + 120000
  retries := 0
  Пока now < deadline:
     Если sendButton visible: успех, вернуть.
     busy := evaluate: найти бейдж с текстом "server busy" / "retry" ...
     Если busy:
        Если retries >= 5: throw
        retries++
        click(busy.x, busy.y)  // клик по бейджу = retry
        wait 4000ms
        continue
     wait 500ms
  throw "Send did not become enabled within 120s"
```

### Граничные случаи

- **Файл отклонён по формату.** Ловится по тексту "format not supported".
- **Плашка "Server busy".** Ретрай до 5 раз.
- **Таймаут 120 секунд.** Throw с указанием retry-счётчика.
- **Несколько файлов.** Передаются в `setInputFiles` массивом.

### Почему именно так

**Почему клик по координатам, а не по селектору скрепки.** Скрепка
открывает dropdown, а не нативный диалог выбора файла. Прямой
`setInputFiles` через `input[type=file]` надёжнее — не зависит от UI
dropdown. Координатный клик нужен только чтобы dropdown активировал input.

**Почему `Escape` после клика.** Открытый dropdown перехватывает
клики. Escape закрывает его до того, как мы будем работать с input.

**Почему retry по клику на бейдж.** DeepSeek показывает бейдж с ошибкой
«Server busy». Клик по нему — это кнопка «Retry» в UI. Без клика
файл остаётся в состоянии ошибки навсегда.

**Почему 5 попыток и 120 секунд.** Эмпирически: первая ошибка обычно
транзиентная, проходит со второй попытки. Пять попыток с задержкой
4 секунды = 20 секунд активного retry. 120 секунд — общий бюджет на
всю операцию, включая ожидание бейджа.

### Реализация

- `src/chat/ChatController.ts` → `attachFile()`

## F4. Ретрай при «Server busy» в плашке {#f4}
**Статус:** active
**Дата фиксации:** 2026-09-18
**Версия:** 1

### Назначение

Автоматически перезапускать загрузку файла, если DeepSeek вернул
транзиентную ошибку в бейдже.

### Входные данные

- Бейдж с текстом, содержащим `server busy` / `upload failed` / `network error`
  / `retry` / `try again`.

### Выходные данные

Успешная загрузка или исключение после 5 попыток.

### Псевдокод

```
Пока now < deadline:
  Если sendButton enabled — успех.
  busy := evaluate:
     Для каждого SVG path[d^="M10.6074 4.40278"]:
        badge := closest('.ds-animated-size-item')
        text := badge.textContent.toLowerCase()
        Если text matches /server busy|upload failed|.../:
           Вернуть { found: true, x, y, text }
     Вернуть { found: false }

  Если busy.found:
     Если retries >= 5: throw
     retries++
     mouse.click(busy.x, busy.y)
     wait 4000ms
     continue
  wait 500ms
```

### Граничные случаи

- **5 неудачных попыток.** Throw с указанием текста последней ошибки.
- **Бейдж исчез между итерациями.** Цикл продолжит ждать.
- **Разные тексты ошибок.** Regex покрывает типичные формулировки.

### Почему именно так

**Почему клик по бейджу, а не по кнопке Retry.** В UI DeepSeek нет
отдельной кнопки — весь бейдж кликабелен и выполняет retry. Координаты
берутся из `getBoundingClientRect()` самого бейджа.

**Почему regex, а не точное совпадение.** Формулировка меняется
(«Server busy, please try again later» / «Upload failed» / «Network error»).
Regex покрывает все наблюдаемые варианты.

**Почему `x = r.x + 20`.** Клик по левому краю бейджа, где расположена
иконка. Клик по центру может попасть в текст и не сработать.

**Почему 5 попыток.** Больше — растёт время ответа клиенту. Меньше —
не покрывает реальные транзиентные сбои. 5 — эмпирический компромисс.

### Реализация

- `src/chat/ChatController.ts` → `attachFile()` (retry loop)
